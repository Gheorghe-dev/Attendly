Everything around the check-in

Attendly brings the class roster, the active session, and attendance review together in one instructor-managed app.

QR

Session QR codes

Open an attendance session and present its check-in QR code to the class. Close the session when check-in ends.

LIVE

Live session monitor

See incoming check-ins update on the instructor dashboard, with a roster and a running attendance count.

XLS

Bring an existing student list into a course from Excel, or add and manage roster entries in the app.

Export session attendance and course records into spreadsheets for your own review and recordkeeping.

Classroom workflows

From course setup to class report

Set up a course

Designed around the classroom

Instructors control courses and sessions. Students use a phone browser to check in with the link provided by their instructor.

For instructors

Your course, your session

Manage class lists and attendance from one dashboard, whether you teach one seminar or several lecture groups.

  • Create courses and maintain student email and group rosters.
  • Import class lists from Excel and organize groups or sections.
  • Create a dated session with its classroom and eligible groups.
  • Present the session QR, follow check-ins, then close attendance.
  • Export attendance reports for review and recordkeeping.
For students

Check in from your phone

No separate student app is needed. Use the current check-in QR code or the instructor’s approved link in a mobile browser.

  • Connect to the network or link supplied by the instructor.
  • Scan the session code with your camera or QR reader.
  • Enter the same email address used in the course roster.
  • Wait for the on-screen confirmation before closing the page.
  • Ask the instructor if the link is unavailable or a record needs correction.
DATA
Understand where data goes. Attendly stores its records in a local SQLite database on the host by default. If you enable a public tunnel or host it on a network server, requests and data may pass through that provider or network. Follow your institution’s policies, use a strong private authentication secret, restrict server access, and back up the database securely.

Get Attendly running

Pick the instructions for the computer that will host the app. The first setup downloads dependencies and creates a local SQLite database.

Windows

Quick launch or desktop app

Windows 10/11
  1. Install Node.js LTS and Git, or install Docker Desktop.
  2. Open PowerShell in the folder where you want Attendly and clone the repository:
git clone https://github.com/Gheorghe-dev/QrAttendace.git
cd QrAttendace
.\start.bat

For the desktop window, run .\Attendly.bat. To use a browser, open http://localhost:3000. Stop with .\stop.bat or Ctrl+C in the launcher window.

Firewall: only allow network access if students need to reach your host. A tunnel is optional; do not expose the instructor dashboard to an untrusted network.

macOS

Terminal or Docker Desktop

Apple silicon & Intel
  1. Install Node.js LTS and Git, or install Docker Desktop for Mac.
  2. Open Terminal and run:
git clone https://github.com/Gheorghe-dev/QrAttendace.git
cd QrAttendace
chmod +x start.sh stop.sh
./start.sh

Open http://localhost:3000. Keep the Terminal window open while the server is in use; stop with ./stop.sh or Ctrl+C.

Gatekeeper: use the Terminal commands from the downloaded project; macOS does not run the Windows .bat launchers.

Linux

Desktop, VM, or server

Node.js 18+
  1. Install Node.js 18 or newer, npm, Git, and OpenSSL using your distribution’s trusted package manager.
  2. Clone and launch from a terminal:
git clone https://github.com/Gheorghe-dev/QrAttendace.git
cd QrAttendace
chmod +x start.sh stop.sh
./start.sh

Visit http://localhost:3000 on the host. For access from another device, configure the host firewall and a trusted HTTPS reverse proxy, or use the optional tunnel feature.

Server tip: use a managed service (for example systemd) for long-running deployments, and back up the database before upgrades.

Docker

Windows, macOS, or Linux host

No host Node.js
  1. Install and start Docker Desktop, or Docker Engine with the Compose plugin.
  2. Clone the repository. Create a strong authentication secret and save it in a root-level .env file (not .env.example).
# macOS / Linux
printf 'NEXTAUTH_SECRET=%s\n' "$(openssl rand -base64 32)" > .env
docker compose up -d
# Windows PowerShell
$bytes = New-Object byte[] 32
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$secret = [Convert]::ToBase64String($bytes)
$rng.Dispose()
"NEXTAUTH_SECRET=$secret" | Set-Content .env -Encoding ascii
docker compose up -d

Open http://localhost:3000. See logs with docker compose logs -f; stop with docker compose down. Attendance data persists in the attendly-data Docker volume.

Keep the secret private. Compose will refuse to start if NEXTAUTH_SECRET is missing.

Manual Node.js setup: after cloning, copy .env.example to .env, replace NEXTAUTH_SECRET with a random value, run npm install, npx prisma db push, then npm run dev. For a production build, run npm run build followed by npm start.

Connect phones to the host

The app runs on the instructor’s computer or server. Student phones need a route to that host while check-in is open.

Same classroom Wi-Fi

Connect the host and phones to a network that allows devices to communicate. Use the LAN URL shown by your setup or app configuration, and permit the app through the host firewall if prompted.

Network isolation: guest Wi-Fi and campus networks often block device-to-device traffic. Ask your network administrator if the phones cannot connect.

Different networks

The included launcher can start an optional Cloudflare Quick Tunnel. It produces a temporary public HTTPS URL for scanning; share only the generated check-in link and keep the server running.

Privacy: tunnel traffic passes through a third-party network provider. Check institutional policies before using it for student data. A public static GitHub Pages address is not an app server or a student check-in endpoint.

Before you go live

Attendance records are sensitive. Start with sensible account, network, and backup practices.

Where is my data stored?

In the local SQLite database at prisma/dev.db for a normal install. Docker stores it in the named attendly-data volume. Back it up regularly and protect access to the host.

Can GitHub Pages host the app?

No. Pages serves static files and cannot run the Next.js server, APIs, authentication, or SQLite database. Use it for this guide; run Attendly on a computer or server.

Students cannot open the QR link

Confirm the app is running, check that the QR uses a reachable LAN or tunnel URL, and verify the host firewall and Wi-Fi device isolation settings.

How do I stop the app?

Use the matching stop script, run docker compose down for Docker, or press Ctrl+C in the terminal that started the server.

Where is the detailed walkthrough?

The complete tutorial explains setup, course management, Excel import, sessions, reports, backups, and troubleshooting.

Where do I report a problem?
